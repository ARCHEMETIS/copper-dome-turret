## ❓ ต้องเขียนโค้ด Arduino (ภาษา C) ไหม?

**ไม่ต้องเขียนเลย** — แต่ต้องใช้ **Arduino IDE แค่ครั้งเดียว** เพื่ออัปโหลดเฟิร์มแวร์สำเร็จรูป:

1. โหลด Arduino IDE จาก arduino.cc
2. เสียบ Uno เข้า USB
3. เมนู **File > Examples > Firmata > StandardFirmata** → กด **Upload**
4. จบ. หลังจากนี้ logic ทั้งหมดอยู่ฝั่ง Python (ผ่านไลบรารี `pyfirmata2`) ตรงตามกติกา "Python เท่านั้น"

⚠️ **ถ้า Upload ไม่ได้ / ไม่เห็นพอร์ต COM:** บอร์ด Uno ของแจกมักเป็นของ clone ใช้ชิป **CH340** — ต้องลงไดรเวอร์ CH340 ก่อน Windows ถึงจะเห็นพอร์ต (search "CH340 driver windows") อันนี้คนพลาดกันเยอะมาก

⚠️ **ใช้ `pyfirmata2` เท่านั้น อย่าลง `pyfirmata` ตัวเก่า** — ตัวเก่าพังบน Python 3.11 ขึ้นไป (error `AttributeError: module 'inspect' has no attribute 'getargspec'`)

## 📁 โครงสร้างโค้ด

```
Project III/
├── requirements.txt          ← ไลบรารีที่ต้องลง
├── src/                      ← โปรแกรมหลัก
│   ├── config.py             ← ค่าคงที่ทุกอย่าง (ขา pin, มุม servo, ตาราง calibrate) แก้จูนที่นี่ที่เดียว
│   ├── hardware.py           ← คลาส Turret คุยกับ Arduino (pan, feeder, ล้อ, ยิง 1 นัด)
│   ├── camera.py             ← เปิดกล้องมือถือ (Camo/DroidCam)
│   ├── detector.py           ← ตรวจจับตุ๊กตา: HSV (ใช้ได้ทันที) / YOLO (ทางหลัก) สลับได้ใน config
│   ├── ranging.py            ← วัดระยะจากขนาดในภาพ + แปลงระยะ→ความแรงล้อ
│   ├── aiming.py             ← visual servoing หมุนป้อมจนเป้าอยู่กลางภาพ
│   └── main.py               ← UI (tkinter): วิดีโอสด + ปุ่มเลือกเป้า + ปุ่ม FIRE
└── tools/                    ← สคริปต์ช่วย รันแยกทีละตัว
    ├── test_hardware.py      ← ★ รันไฟล์นี้เป็นไฟล์แรก! คุมป้อมด้วยคีย์บอร์ด
    ├── calibrate_focal.py    ← หา FOCAL_PX (วัดระยะจากภาพ) ทำหลังล็อก focus มือถือ
    ├── calibrate_pwm.py      ← ทำตาราง duty↔ระยะ (หัวใจคะแนนยิงแม่น 5 คะแนน)
    └── capture_dataset.py    ← ถ่ายรูปตุ๊กตาไว้เทรน YOLO
```

**Flow ตอนกด FIRE:** เลือกเป้าใน UI → `aiming` หมุนป้อมจนเป้ากลางภาพ → `ranging` วัดระยะจากขนาดกรอบ → interpolate ตารางเป็นความแรงล้อ → `hardware.fire()` (ปั่นล้อ 1.2 วิ → feeder ดันลูก → หยุด)

## 📋 ลำดับงานฝั่งโค้ด (ทำตามลำดับนี้)

1. **อัปโหลด StandardFirmata** ลง Uno (ครั้งเดียว, ดูหัวข้อบนสุด)
2. **`python tools/test_hardware.py`** — พิสูจน์ว่า servo หมุน, ล้อหมุน, feeder ดัน, ยิงลูกออก (= 5 คะแนนแรกของเกณฑ์) ระหว่างนี้จูน `FEEDER_REST` / `FEEDER_PUSH` ใน config.py จากของจริง
3. **ต่อมือถือผ่าน Camo** → รัน `python tools/capture_dataset.py` เช็คว่า OpenCV อ่านภาพได้ (ถ้าไม่เจอกล้อง ตั้ง `CAMERA_INDEX` ใน config)
4. **ล็อก focus + exposure ใน Camo** แล้วรัน `python tools/calibrate_focal.py` → เอาค่าไปใส่ `FOCAL_PX`
5. **รัน `python src/main.py`** ด้วย detector = "hsv" กับไดโนเสาร์เขียวก่อน (สีเขียวแยกง่ายสุด) → ได้ระบบครบ loop เร็วที่สุด
6. ✅ **ถ่ายรูป + เทรน YOLO** (ดูหัวข้อล่าง) → สลับ `DETECTOR = "yolo"` → ครบ 3 ตัว — **เทรนแล้ว 2 รอบ** (รอบ 2: 10 ก.ค. 2026, mAP50 0.968 valid / 0.937 test บนชุดที่มีท่าวางแปลกๆ)
7. **`python tools/calibrate_pwm.py`** ยิงจริงหลายระยะ ทำตาราง → วางทับ `PWM_DISTANCE_TABLE`
8. ซ้อมยิงเก็บสถิติ + จูน `AIM_KP` / `AIM_DEADBAND_PX` ถ้าเล็งส่ายหรือช้า

## 🧠 เทรน YOLO (ทางหลักของ vision)

**✅ เสร็จแล้ว (8 ก.ค. 2026)** — สรุปสิ่งที่ทำจริง ไว้เทรนซ้ำ/เทรนเพิ่มทีหลังได้:

1. ถ่ายรูปเอง 770 รูป (มือถือ, หลายระยะ/มุม/แสง/ฉากหลัง) label เองทั้งหมดผ่าน **Roboflow** (ใช้ Label Assist ช่วยตีกรอบเบื้องต้นแล้วรีวิว/แก้เอง) — ไม่ใช่ makesense.ai ตามแผนเดิม เพราะ Roboflow มี AI ช่วยตีกรอบ เร็วกว่ามากตอนรูปเยอะ
2. Export จาก Roboflow เป็น **YOLOv8 format** (zip: `train/`, `valid/`, `test/`, `data.yaml`) วางทับ `dataset/` ทั้งโฟลเดอร์
3. ⚠️ **ลำดับ class ที่ได้จริงไม่ตรงกับที่วางแผนไว้แต่แรก** — Roboflow เรียงตามตัวอักษร: `0=capybara, 1=dino, 2=elephant` (ไม่ใช่ 0=dino,1=capybara,2=elephant ตามที่เขียนไว้เดิม) ต้องเช็ค `dataset/data.yaml` หัวข้อ `names:` ทุกครั้งหลัง export ใหม่ แล้วแก้ `yolo_class` ใน `config.py` ให้ตรง — ห้ามเดาลำดับเอาเอง
4. ⚠️ **ห้ามใช้ split ที่ Roboflow แบ่งให้อัตโนมัติตรงๆ** — รูปหลายร้อยรูปเป็นเฟรมที่ตัดมาจากวิดีโอเดียวกัน (เช่น `IMG_3481_frame_001, 002, 003...`) เกือบเหมือนกันทุกพิกเซล ถ้าปล่อยให้ Roboflow สุ่มแบ่งทีละรูปแบบ default เฟรมพี่น้องกันจะกระจายไปทั้ง train และ valid/test พร้อมกัน → โมเดลเห็นฉากเกือบเดียวกันตอนเทรนแล้วมาวัดผลซ้ำ ทำให้ mAP สูงเกินจริง (data leakage) **ต้องรันก่อนเทรนทุกครั้งที่ export ใหม่:**
   ```powershell
   python tools/resplit_dataset.py
   ```
   สคริปต์นี้จะรวมรูปทั้ง 3 split กลับมาเป็นกองเดียว จัดกลุ่มตามคลิปต้นทาง แล้วแบ่งใหม่ให้ทั้งกลุ่มอยู่ split เดียวกันเสมอ (~70/20/10) พร้อมเช็คให้ว่าไม่มีกลุ่มไหนรั่วข้าม split
5. เทรนด้วย GPU (`device=0`) เร็วกว่า CPU มาก (~10-15 นาที ต่อ 60 epochs บน RTX 4050 เทียบกับหลายชั่วโมงบน CPU) ต้องลง PyTorch build ที่มี CUDA ก่อน (`pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124`) ค่า default ที่ลงตาม requirements.txt เป็น CPU-only:
   ```powershell
   yolo train model=yolov8n.pt data=dataset/data.yaml epochs=60 imgsz=640 device=0
   ```
6. ผลลัพธ์ (บน split ที่ไม่มี leak แล้ว): รอบแรก (8 ก.ค., 770 รูป) mAP50 **0.988** | **รอบ 2 (10 ก.ค., 1,369 รูป)** mAP50 **0.968 valid / 0.937 test** — เทียบตรงๆ กับรอบแรกไม่ได้เพราะชุดทดสอบรอบ 2 โหดกว่ามาก (ท่าหงายท้อง/หัว-ตูดจ่อกล้อง/ถูกถือกลางอากาศ/เฟรมเบลอ/ระยะไกล) **ผลเทียบยุติธรรม** (รันทั้งสองโมเดลบนรูปชุดใหม่ 71 รูปที่ต่างฝ่ายต่างไม่เคยเห็น): เก่า→ใหม่ recall 0.901→**0.986**, mAP50 0.942→**0.992** — กำไรจริงของรอบ 2 คือหาเจอท่าแปลก ไม่ใช่ precision (ซึ่งสูงอยู่แล้วทั้งคู่) — ไฟล์อยู่ที่ `runs/detect/train-2/weights/best.pt` copy มาไว้ `models/best.pt` (ตัวเก่า backup เป็น `models/best_2026-07-09_เทรนรอบแรก.pt`) — **`models/best.pt` commit เข้า git ไว้แล้ว** (แก้ `.gitignore` ให้ยกเว้นไฟล์นี้จาก `models/*.pt` โดยเฉพาะ เพราะถ้าไม่ commit ไว้ clone ใหม่ที่ไหนก็ตามจะรัน `--sim` ไม่ได้เลย เพราะ `YoloDetector` โหลดไฟล์นี้แบบ hard-code)
   - **ขั้นตอนเทรนรอบใหม่แบบขี้เกียจ label:** `tools/auto_label.py <โฟลเดอร์รูปใหม่>` ให้โมเดลปัจจุบันตีกรอบก่อน → ลากผลขึ้น Roboflow โปรเจคใหม่ (โปรเจคเดิมจะเจอรูปซ้ำแล้ว label ไม่ติด) → รีวิว/ลบกรอบผี/ลากกรอบรูปที่หาไม่เจอ → export YOLOv8 → รวมกับชุดเดิม → `resplit_dataset.py` → เทรน
   - ⚠️ **ค่า ranging ผูกกับโมเดล:** `real_size_mm` ใน config คาลิเบรตจากนิสัยการตีกรอบของโมเดล — เปลี่ยนโมเดลแล้วต้องเก็บข้อมูลระยะใหม่ (`tools/collect_ranging_data.py`) แล้ว fit ค่าใหม่เสมอ
7. ทดสอบแบบไม่ต้องมีตุ๊กตาจริง: `python tools/test_on_webcam.py` (เว็บแคมสด) หรือ `python tools/test_on_video.py` (จากไฟล์วิดีโอ) ทั้งคู่แชร์โค้ด predict+วาดกรอบร่วมกันผ่าน `tools/_yolo_preview.py`

**ทางลัดถ้าเวลาไม่พอ:** ใช้ HSV กับไดโนเสาร์เขียวให้เสถียร แล้ววันจริงเลือกยิงไดโนเป็นหลัก — เกณฑ์บอกแค่ "ยิงถูกตัวที่เลือก 5/10" ไม่ได้บังคับว่าต้องสลับตัว (เช็คกับอาจารย์อีกทีว่ากรรมการเป็นคนเลือกเป้าหรือเราเลือกเอง — ถ้ากรรมการเลือก ต้องทำ YOLO ให้ครบ 3 ตัว)

## ⚠️ สิ่งที่คนไม่รู้แล้วเจ็บบ่อย (จดจากประสบการณ์)

| อาการ | สาเหตุ/ทางแก้ |
|---|---|
| ไม่เห็นพอร์ต COM | ลงไดรเวอร์ CH340 (บอร์ด clone) |
| `pyfirmata` error ตอน import | ใช้ `pyfirmata2` แทน (Python 3.11+) |
| Uno รีเซ็ตเอง/servo กระตุก | servo ดึงไฟจาก USB — ต้องถอด jumper บน shield แล้วจ่าย 6V จาก buck + **ต่อ GND ร่วมทุกส่วน** |
| ต่อ serial แล้วสั่งอะไรไม่ติดช่วงแรก | เปิด serial = Uno รีเซ็ตตัวเอง ต้องรอ ~2 วิ (โค้ดใน hardware.py รอให้แล้ว) |
| ล้อหมุนแต่ลูกไม่พุ่ง / ลูกถูกดูดกลับ | ล้อ 2 ข้างต้องหมุนสวนกัน — สลับสาย IN คู่ใดคู่หนึ่ง (ดูคอมเมนต์ hardware.py) |
| duty ต่ำแล้วล้อไม่หมุนเลย | ปกติ — L298N กินแรงดันไป ~2V ด้วย ตั้ง `FLYWHEEL_MIN_DUTY` จากที่ทดลองจริง |
| ป้อมหมุน "หนี" เป้า | ทิศ servo กลับด้านกับภาพ — เปลี่ยน `AIM_SIGN = -1` ใน config |
| วัดระยะเพี้ยนหลังจากเคยแม่น | มือถือ auto-focus เปลี่ยนค่า — ต้องล็อก focus แล้ว calibrate ใหม่ |
| ภาพจาก Camo หน่วง/ค้าง | ต่อ USB แทน WiFi, ปิดแอปอื่นบนมือถือ, ลดความละเอียดเหลือ 720p ก็พอ |
| ยิงแล้วนัดถัดไปพลาด | recoil ทำป้อมขยับ — โค้ด aiming เล็งใหม่ทุกนัดอยู่แล้ว แต่ฐานต้องหนัก/ยึดแน่นด้วย |
| tkinter UI ค้างตอนยิง | ห้ามเรียก aim/fire ใน main thread — main.py ใช้ thread แยกให้แล้ว อย่าแก้ทิ้ง |

## 💡 เคล็ดลับวันตัดสิน

- มือถือ: โหมดเครื่องบิน + ปิดแจ้งเตือน + แบตเต็ม + **ล็อก focus ค่าเดิมกับตอน calibrate**
- ถึงหน้างานก่อนเวลา → calibrate focal ใหม่กับแสงจริงถ้าทำได้ (ใช้เวลา 2 นาที)
- คัดลูกบอลไม้น้ำหนักใกล้กัน ~15 ลูกไว้ใช้จริง (ชั่งด้วยตาชั่งครัว)
- อัดวิดีโอยิงโดนไว้ก่อนวันจริงเสมอ (backup ตอนนำเสนอถ้าหน้างานพัง)
- แบต 18650 ชาร์จเต็ม + มีสำรอง — แรงดันตกทำให้ curve PWM↔ระยะเพี้ยนทั้งตาราง
  (ถ้าซ้อมตอนแบตเต็มแล้วแข่งตอนแบตอ่อน ลูกจะตกสั้นกว่าที่ calibrate ไว้!)
