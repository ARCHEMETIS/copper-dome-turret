# 🎯 Runbook: จูนความแม่น pan/tilt (โหมดสโคป)

> เป้าหมาย: หมุนป้อมให้เป้ามาอยู่ "จุด zero" ของสโคปแม่นที่สุด
> **ลำดับสำคัญมาก** — ทำผิดลำดับจะไล่แก้ปัญหาไม่เจอ (gain/sign ผิดจะโผล่เป็น "zero เพี้ยน" ทีหลัง)
> โค้ดที่เกี่ยว: `src/aiming.py` (`aim_at`), ค่าปรับทั้งหมดอยู่ `src/config.py` ส่วน "Visual servoing"

## ทำไมต้องเรียงลำดับนี้
`aim_at` = วนลูป: อ่านเฟรม → หา error จากจุด zero → หมุน `AIM_KP × error` (จำกัด `AIM_MAX_STEP_DEG`) → รอ `AIM_SETTLE_S` → ซ้ำ จนอยู่ในกรอบ `AIM_DEADBAND_PX` ติดกัน `AIM_CONFIRM_FRAMES` เฟรม
→ ถ้า **ทิศ (sign) ผิด** ป้อมจะหมุน "หนี" เป้า (ยิ่งเพี้ยน) | ถ้า **gain ผิด** จะส่าย (สูงไป) หรือคลานช้าจน timeout (ต่ำไป) | **zero** คือ offset สุดท้ายที่ทำให้ "เล็งตรงจุด = โดนจริง" — ต้องตั้งหลังทุกอย่างนิ่งแล้ว

## Step 0 — เตรียม
- [ ] ต่อ Arduino (COM7) + กล้อง Camo (index 1) — `test_hardware.py` เช็ค servo pan/tilt ขยับได้ (ปุ่ม A/D), `main_click.py --webcam` เห็น detection
- [ ] เป้า 3 ตัววางระดับโต๊ะเดียวกัน, ป้อมอยู่ต่ำกว่า (ตามเงื่อนไขจริง)
- [ ] **เช็คกล้องยึดแน่นกับลำกล้อง** — recoil ห้ามทำ zero เลื่อน (ถ้าเลื่อน จูนเท่าไหร่ก็ไม่นิ่ง)

## Step 1 — ทิศทาง `AIM_SIGN` / `AIM_TILT_SIGN` (สำคัญสุด ทำก่อน)
วางเป้าให้อยู่ **ซ้าย/ขวาชัดๆ ของจุด zero** → คลิกล็อก → ดูป้อมหมุน**รอบแรก**:
| อาการ | แก้ |
|---|---|
| ป้อมหมุน **เข้าหา**เป้า (error ลด) | ✅ `AIM_SIGN` ถูกแล้ว |
| ป้อมหมุน **หนี**เป้า (error โต/วิ่งชนขอบ PAN_MIN/MAX) | สลับ `AIM_SIGN` เป็น `-1` |

ทำ **แนวตั้งแยกต่างหาก** (เป้าสูง/ต่ำกว่า zero) → ถ้าเงยหนี สลับ `AIM_TILT_SIGN` เป็น `-1`
⚠️ อย่าข้ามไปทำ zero ถ้าข้อนี้ยังไม่ชัวร์ — ทิศผิดคือรากของทุกปัญหา

## Step 2 — gain `AIM_KP` (ปัจจุบัน 0.03)
เพดานทฤษฎี (unity) ≈ `1/FOCAL_PX` = **0.041 °/px** — อยู่ **ต่ำกว่านี้ = ไม่ overshoot**
| อาการ | แก้ |
|---|---|
| ป้อม**ส่าย**ไปมารอบ zero ไม่นิ่ง | ลด `AIM_KP` (เช่น 0.02) |
| ป้อม**คลานช้า** เข้าไม่ทัน (timeout 12s) | เพิ่ม `AIM_KP` (เข้าใกล้ 0.04 แต่ไม่เกิน 0.041) |
| นิ่งเร็ว ไม่ overshoot | ✅ พอดี |

## Step 3 — `AIM_FLUSH_FRAMES` (ทิ้งเฟรมค้าง — knob ใหม่ 22 ก.ค.)
แก้อาการ servo "เล็งจากภาพก่อนหมุน" (`aim_at` อ่านเฟรมเก่าใน buffer). **ค่าเริ่ม `0` (ปิด)** —
ยังไม่ยืนยันบนกล้องจริงว่าจำเป็น (ถ้า buffer กล้องตื้นจะยิ่งเพิ่ม latency เปล่าๆ) → **เปิดตรงนี้เฉพาะเมื่อเจออาการจริง**
| อาการ | แก้ |
|---|---|
| ยัง**ส่ายตามภาพเก่า** (หมุนเกินแล้วค่อยรู้ตัว) แม้ gain โอเค | เพิ่มเป็น 3-4 |
| รู้สึก**หน่วง/ช้า** ไม่เห็นต่าง | ลดเป็น 0 (ปิด) |

## Step 4 — `AIM_DEADBAND_PX` เทียบ servo slop
ปัจจุบัน 15px = **0.61°** ที่ FOCAL_PX 1400 | วัด slop MG945 จริงก่อน (สั่งมุมเล็กไป-กลับ ดู "ระยะฟรี")
- ถ้า slop > deadband → ป้อม**ส่ายในเขต slop ไม่จบ** → เพิ่ม `AIM_DEADBAND_PX` ให้ ≥ pixel-equivalent ของ slop
- `AIM_CONFIRM_FRAMES` (3) ช่วยกรอง transient — เพิ่มถ้ายอมรับช้าลงเพื่อความชัวร์

## Step 5 — คาลิเบรต `SCOPE_ZERO_OFFSET_PX` (**ทำท้ายสุด**)
ตอนนี้ `[0, 0]` (ยังไม่ตั้ง). ทำหลัง Step 1-4 นิ่งหมดแล้วเท่านั้น:
1. ยิงจริงใส่เป้าที่ระยะกลาง → ดูว่า**ลูกไปโดนตรงไหน**เทียบจุดเล็งกลางจอ
2. ปุ่ม **I/J/K/L** ใน `main_click` ขยับ zero (บน/ซ้าย/ลง/ขวา) จนจุดเล็ง = จุดโดนจริง
3. จดค่าลง `config.SCOPE_ZERO_OFFSET_PX`
⚠️ ต้อง **แรงยางนิ่งทุกนัด** (ยางล้า → ตัวไกลตกต่ำ zero เดียวเอาไม่อยู่) + ยิงหลายนัดเช็คซ้ำ

## Step 6 — validate
ไล่ 3 เป้า × ระยะ near/mid/far (1.5–2.4m) → ต้องโดนสม่ำเสมอ
⚠️ ถ้า**ใกล้โดนแต่ไกลตก** = สมมติฐาน "วิถีแบนคุ้มทั้งช่วง zero เดียว" ไม่จริง → ต้องคุยเรื่องชดเชยมุมเงยตามระยะ (ดู TODO `config.py:97-98`)

## ปมฟิสิกส์ที่โค้ดแก้ไม่ได้ (เตือนไว้)
- **กล้องต้องยึดแน่นกับลำกล้อง** — ขยับนิดเดียว zero เพี้ยนหมด
- **แรงยางสม่ำเสมอ** — ล้า/อุ่นเครื่องต่างกัน = ระยะตกต่างกัน
- **มือถือวางใกล้แกน tilt** — โมเมนต์บน MG945 น้อยลง เงยแม่นขึ้น
- servo slop เป็นเพดานความแม่น (MG945 ±1–2.5° ตามที่เคยถกวันแรก) — ถ้าไม่พอ พิจารณาลด backlash เชิงกล (สปริงดึงทางเดียว) มากกว่าแก้โค้ด
