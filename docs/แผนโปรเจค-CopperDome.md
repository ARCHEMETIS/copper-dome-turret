## 2. แนวคิดหลัก (แก้โจทย์ "ทุกระยะ")

1. **กล้อง fix บนเสาเหนือแกนหมุน (ตัดสินใจแล้ว 6 ก.ค.)** — มือถือไม่หมุนตามป้อม ติดบนเสาที่ยึดกับฐาน โดยแกนกล้องตรงกับแกน pan พอดี (กันปัญหา parallax) ข้อดี: ป้อมเบา servo ไม่แบกมือถือ, ไม่มีสายบิด, เห็นโต๊ะทั้ง 2.4 m ในเฟรมเดียว UI คลิกเลือกเป้าได้เลย
   - แปลง pixel → มุม pan ด้วยตาราง calibrate: วางวัตถุ 4–5 ตำแหน่ง จดคู่ (pixel x, มุม servo ที่ยิงโดน) แล้ว interpolate
   - **Closed-loop ด้วย marker:** แปะจุดสี/sticker ที่ปลายลำกล้อง กล้องเห็นทั้งเป้าและ marker → สั่งหมุนจน marker อยู่แนวเดียวกับเป้า = มี feedback ยืนยันว่าชี้ถูกจริง
2. **วัดระยะจากขนาดวัตถุ** — รู้ขนาดจริงตุ๊กตาแต่ละตัว → ระยะ = focal × ขนาดจริง ÷ ขนาด pixel (ต้องล็อก focus/exposure ก่อน calibrate)
3. **คุมระยะยิงด้วย PWM + calibration curve** — มุมเงยล็อกตายตัว (~25–30°) ตัวแปรเดียวคือความเร็วล้อ ยิงจริงหลายระยะทำตาราง PWM↔ระยะ แล้ว interpolate (สูตรฟิสิกส์ projectile ใช้ประกอบสไลด์)

### จังหวะการยิง 1 นัด
เลือกเป้าใน UI (เห็นทั้ง 3 ตัวในเฟรม) → คำนวณมุม pan จาก pixel → หมุนป้อม + เช็ค marker ลำกล้องตรงแนวเป้า → วัดระยะจากขนาดเป้า → ตั้ง PWM ล้อ → รอล้อเต็มรอบ ~1 วิ → feeder servo ดันลูก → ยิง → servo ถอยกลับ ลูกถัดไปไหลลงจุดรอเอง

### หน้าที่ servo (มีแค่ 2 ตัว — ไม่มี tilt servo)
- **MG945 ตัวที่ 1 = pan:** ตัว servo ยึดกับฐานใน bracket, horn ขันติดแท่นหมุน โต๊ะเป้ากว้าง 2.4 m ที่ ~1.5 m ใช้กวาดแค่ ±40° (servo ได้ 180°)
- **MG945 ตัวที่ 2 = feeder:** แขนดันลูกเข้าล้อ (แทนมอเตอร์ตัวที่ 3 ของดีไซน์ XRP เดิม) ไม่เกี่ยวกับการเล็ง
- **มุมเงย (tilt) ไม่มี servo:** ล็อกตายตัว ~25–30° ปรับระยะด้วย PWM แทน + ทำจุดยึดแบบขันน็อตเลือกมุมได้ 2–3 ระดับ (20°/30°/40°) ไว้ปรับมือหน้างานกรณี PWM สุดช่วงแล้วไม่พอ
- สรุป: โค้ดเล็งเหลือแค่ 2 ตัวเลข = มุม pan กับค่า PWM

## 2.5 การตัดสินใจ 18 ก.ค. — เปลี่ยนกลไกยิงเป็นหน้าไม้ (crossbow)

### สรุปผล (ตอบเกณฑ์ 5 คะแนน "สร้างกลไกยิงกระสุนออกได้" — issue #1)

**ไม่ได้ทดสอบ flywheel+มอเตอร์ TT จริงบนโต๊ะ** — ข้ามไปเลือกกลไกสำรองตั้งแต่ต้น เพราะมอเตอร์ที่ได้รับ
เป็น **TT gear motor (~200 rpm มีเกียร์)** ตรงกับเงื่อนไขความเสี่ยงที่วางแผนไว้ล่วงหน้าแล้วใน §9
("มอเตอร์เป็นแบบมีเกียร์ หมุนช้า → เปลี่ยนเป็นสปริง+servo ปลดล็อก") — flywheel ต้องการมอเตอร์เปลือย
หมุนเร็ว (130/280-type) ไม่ใช่มอเตอร์มีเกียร์ จึงไม่คุ้มเวลาที่จะขึ้นเฟรมพิมพ์ 3D ทดสอบแล้วพังตามคาด
เปลี่ยนไปกลไกสำรอง (สปริง/ยางยืด + ปลดล็อกด้วยมอเตอร์) ที่วางแผนไว้แล้วทันที

**สถานะยิงจริง ≥1.5 m: ยังไม่ยืนยัน** — ต้องประกอบ+ทดสอบของจริงก่อนถึงจะปิด acceptance criteria
ข้อ 3 ได้ ใช้ `tools/test_hardware.py` (คีย์ `t`/`f`) หรือ `tools/calibrate_angle.py` ทดสอบแล้วมาบันทึกผล
ต่อท้ายหัวข้อนี้

### กลไก

- **Pan/tilt ด้วย servo 2 ตัว (MG945 เดิมทั้งคู่):** servo ตัวที่ 1 หมุนป้อมซ้าย-ขวา (เหมือนแผนเดิม)
  servo ตัวที่ 2 (เดิมเผื่อไว้เป็น feeder) ย้ายมาคุมมุมเงยแทน โดยขบกับเฟือง rack (ซี่ฟันตรง) ที่ยื่นลง
  มาจากฐานป้อมด้านบน — หน้าไม้ไม่ต้องมี feeder ดันลูกแบบ flywheel เดิมแล้ว (แมกกาซีน gravity-feed
  ทำหน้าที่นั้นแทน) จึงย้าย servo ตัวที่ 2 มาใช้ตรงนี้ได้พอดี ไม่ต้องซื้อเพิ่ม
- **ดึงสายด้วยมอเตอร์ DC 2 ตัวเดิม (ย้ายจาก flywheel):** ออกแบบเป็น**เฟืองครึ่งวง (half-gear /
  slip-gear)** — มอเตอร์หมุนทิศเดียวต่อเนื่อง ดึงยาง/สายจนถึงจุดที่ฟันเฟืองหมด → หลุดเอง → ยางดีดลูก
  ออก → หมุนต่อกลับตำแหน่งพร้อมยิงใหม่เอง (self-cycling) เป็น concept เดียวกับที่ร่างไว้ใน
  `tools/test_catapult.py` (ต้นแบบทดสอบ XRP catapult ก่อนหน้านี้) เอามาปรับใช้กับหน้าไม้
- **แมกกาซีน gravity-feed อัตโนมัติ:** ป้อนลูกบอลไม้เข้ารางหน้าไม้เองทุกนัด ไม่ต้องมือป้อนระหว่าง
  ยิง 10 นัด
- **คุมระยะด้วยมุมเงย 100% แทน PWM:** หน้าไม้แรงดึงคงที่ทุกนัด (ระยะดึงจากเรขาคณิตเฟืองตายตัว)
  ต่างจาก flywheel ที่คุมระยะด้วยความแรงมอเตอร์ — จึงต้องคุมระยะด้วยมุมเงยแทน (`TILT_ANGLE_TABLE`
  ใน `config.py`, แทนที่ `PWM_DISTANCE_TABLE` เดิม) ข้อดีคือได้สูตร ballistics มุม-ระยะจริงไปพรีเซนต์
  ตรงเกณฑ์ "รายการคำนวณการเคลื่อนที่กระสุน" พอดี

### จุดเสี่ยงที่ต้องระวังตอนประกอบ/ทดสอบจริง

1. **มอเตอร์ดึง 2 ตัวต้องหมุนพร้อมกันไม่เพี้ยน** — มอเตอร์แปรงถ่านราคาถูกความเร็วไม่เท่ากันแน่ๆ
   (~5-10%) ถ้าดึง 2 จุดของสายอิสระกันอาจบิด/เยื้อง ถ้าเป็นไปได้ให้ต่อเพลาร่วมกันจริงตอนประกอบ
   ดีกว่าปล่อยให้แต่ละตัวดึงคนละข้างอิสระ
2. **จับจังหวะ "ดึงสุด/พร้อมยิง" ด้วยสวิตช์โฮมเมด ไม่ใช่นับเวลา** — เพราะมอเตอร์ความเร็วไม่คงที่จริง
   (ไฟตกตอนออกตัว เจอมาแล้วกับ flywheel 15 ก.ค., ดู `FLYWHEEL_RAMP_STEP`/soft-start ใน commit
   `bf55023`) และงบไม่พอซื้อ limit switch เพิ่ม จึงใช้**สวิตช์โฮมเมด**แทน: ลวด/แผ่นโลหะเล็กๆ ติดกับ
   เฟืองดึง แตะสาย GND แค่ตอนอยู่ตำแหน่งพร้อมยิง (1 จุดสัมผัสต่อ 1 รอบ) ต่อเข้าขา digital พร้อม
   internal pull-up ของ Arduino (`config.PIN_CAM_SWITCH`, ไม่ต้องมีตัวต้านทานเพิ่ม) — โค้ดอยู่ใน
   `Turret.draw_and_release()` (`src/hardware.py`) มี timeout กันมอเตอร์หมุนไม่หยุดถ้าสายสวิตช์หลุด
3. **Servo tilt ต้องแบกน้ำหนักชุดบนทั้งหมด** (มอเตอร์ดึง 2 ตัว + เฟือง + ตัวหน้าไม้) — แผนเดิมตัดสินใจ
   ไม่ใส่ tilt servo ไปแล้วเพราะเหตุผลนี้โดยตรง (ดู §2 เดิมด้านบน, บรรทัด "มุมเงย (tilt) ไม่มี servo")
   **ขัดกับแผนเดิมโดยตรง แต่เปิดใหม่เพราะ**สถานการณ์เปลี่ยน (ไม่มี flywheel/feeder ให้แบกแล้ว น้ำหนัก
   ชุดบนอาจไม่ต่างจากเดิมมาก) — ควรชั่งน้ำหนักชุดบนคร่าวๆ เทียบแรงบิด MG945 (~10 kg·cm) ก่อนขันยึด
   ถาวร ถ้าไม่ไหวค่อยกลับไปใช้มุมเงยตายตัว + ปรับ `TILT_MIN`/`TILT_MAX`/`TILT_CENTER` ให้เท่ากัน
4. `TILT_MIN`/`TILT_MAX`/`TILT_CENTER`/`DRAW_DUTY`/`DRAW_TIMEOUT_S` ใน `config.py`
   **ทั้งหมดยังเป็น placeholder** ต้องวัด/คาลิเบรตจากของจริง (ดู `tools/test_hardware.py`)

  พิกเซลบนจอที่คาลิเบรตจากการยิงจริงว่า "เป้าอยู่ตรงนี้ = โดน" (`SCOPE_ZERO_OFFSET_PX`
  ใน config, เลื่อนด้วยปุ่ม I/J/K/L ใน `main_click.py` แล้วจดค่าลง config)
- **tilt servo เปลี่ยนหน้าที่จาก "ตั้งมุมตามระยะ" → "แกนเล็งแนวตั้ง"** — visual servoing
  ทำงาน 2 แกนพร้อมกัน (pan เอาเป้าเข้าแนวตั้งจุด zero, tilt เอาเข้าแนวนอน)
- **ผลต่อโค้ด:** ตัด `TILT_ANGLE_TABLE`/`calibrate_angle.py`/`angle_for_distance()` ทิ้ง
  `fire()` ไม่รับมุมแล้ว (เล็งเสร็จก่อนยิง) — `ranging.distance_mm` เหลือไว้โชว์ HUD +
  ประตูกัน ghost เท่านั้น
- **วิธี zero (ทำครั้งเดียวหลังประกอบ):** ยิงที่ระยะกลาง (~2m) → ดูจุดที่ลูกโดนบนจอ →
  เลื่อนจุด zero ให้ทับ → ยืนยันด้วยการยิงตัวใกล้สุด+ไกลสุด ถ้าตัวไกลตกต่ำ = ยางแรงไม่พอ
  ต้องเพิ่มแรงยาง (วิถียังแบนไม่พอ) ไม่ใช่แก้จุด zero
- **เงื่อนไขความแม่น 2 ข้อ:** ① กล้องยึดแน่นกับลำกล้อง recoil ห้ามทำ zero เลื่อน
  ② แรงยางเท่ากันทุกนัด (เฟืองครึ่งวงดึงระยะคงที่ช่วยอยู่แล้ว แต่ยางล้า = ตัวไกลเริ่มตกต่ำ)
- **ความเสี่ยงใหม่:** มือถือ (~200g) ขึ้นไปเกาะชุดที่เงย → โมเมนต์บน tilt servo เพิ่ม
  ให้วางใกล้แกนหมุนเงยที่สุด และเช็คว่า MG945 (~10 kg·cm) แบกไหวก่อนขันถาวร

## 3. อุปกรณ์และหน้าที่

| อุปกรณ์ (ที่ได้รับแจก) | หน้าที่ |
|---|---|
| Arduino Uno R3 + Sensor Shield v5 | ตัวกลางรับคำสั่งจาก Python (StandardFirmata) |
| DC Motor 3–6V ×2 + L298N | ล้อหมุนคู่ (flywheel) — PWM คุมความเร็ว = คุมระยะ |
| MG945 ตัวที่ 1 | Pan หมุนป้อม (torque ~10 kg·cm) |
| MG945 ตัวที่ 2 | Feeder ดันลูกเข้าล้อทีละลูก |
| 18650 ×2 อนุกรม (7.4V) | จ่าย L298N ตรง + เข้า buck |
| DC-DC step-down (buck) | ตั้ง 6V เลี้ยง servo (ห้ามเลี้ยงจาก 5V ของ Uno) |
| Diode ×2, Cap 100uF ×2 | กัน noise/ไฟกระชากจากมอเตอร์ |
| ตัวต้านทานปรับค่า 10k | จูนความเร็วล้อแบบ manual ตอนทดสอบ |

**ต้องหาเอง (ไม่ซื้อ):** มือถือ (เป็นกล้อง), ล้อ flywheel พิมพ์ 3D + หุ้มยาง (โอริง/ยางรัด/ยางใน), เสากล้อง, โครง/แผ่นฐาน, ท่อแมกกาซีน, ลูกบอลไม้สำรอง

⚠️ **เช็คด่วน:** มอเตอร์ DC ต้องเป็นแบบเปลือยหมุนเร็ว (130/280-type) ถ้าเป็น TT motor มีเกียร์ (หมุนช้า ~200 rpm) → เปลี่ยนแผนเป็นสปริง + servo ปลดล็อกทันที

## 4. กล้องมือถือ (iOS ใช้ได้)

- **Camo** (แนะนำ iOS): ต่อ USB, มี manual exposure/WB, ฟรี 1080p (ลายน้ำเล็ก crop ทิ้งได้) — ต้องลง iTunes/Apple Devices บน Windows ก่อน

- Python อ่านผ่าน `cv2.VideoCapture(index)` ไล่ index จนเจอ
- **ล็อก focus + exposure เสมอ แล้วค่อย calibrate** และห้ามแตะ setting อีก
- ติดตั้ง: เสายึดกับฐาน (ไม่หมุน) เหนือแกน pan พอดี มองเห็นทั้งป้อม (marker) และโต๊ะเป้าทั้ง 2.4 m
- วันจริง: โหมดเครื่องบิน + ปิด notification + แบตเต็ม

## 5. Vision — แยกตุ๊กตา 3 ตัว

- ทางหลัก: fine-tune **YOLOv8n** จากรูปตุ๊กตาจริง ~100–150 รูป/ตัว (ได้ทั้ง label + กรอบไว้วัดระยะ, ทนแสง/ระยะ, พูดเรื่อง algorithm ในสไลด์ได้เต็มปาก)
- ทางสำรอง: HSV segmentation (เขียว=ไดโนเสาร์ ง่าย แต่คาปิบาร่า/ช้างสีจืด เสี่ยง)
- เพิ่มเติม: ตรวจจับ marker สีที่ลำกล้องด้วย HSV ง่ายๆ (เลือกสีที่ไม่ชนกับตุ๊กตา เช่น ฟ้าสด/ชมพูสะท้อนแสง)

## 6. โครงสร้างและการประกอบ

### หลักการ flywheel shooter (ดีไซน์ XRP)
ล้อยาง 2 ล้อหมุนสวนทางกันค้างไว้ (มอเตอร์ DC ×2 — ต่อสายตัวหนึ่งกลับขั้วที่ L298N ก็หมุนสวนกันแล้ว รับ PWM เดียวกัน) ช่องระหว่างล้อแคบกว่าลูก 1–2 mm พอ feeder ดันลูกเข้าไป ผิวล้อหนีบแล้วสะบัดออกด้วยความเร็วเท่าผิวล้อ → ความเร็วลูก = ตามรอบมอเตอร์ = คุมด้วย PWM

**ไฟล์ในชุด XRP (printables.com/model/951454, เป็น STEP แก้ CAD ได้):**

| ไฟล์ | คืออะไร |
|---|---|
| Two Motor Flywheel v42 | เรือนหลัก เสียบมอเตอร์ 2 ตัว + ช่องทางเดินลูก |
| 50mm Flywheel v5 | ตัวล้อ (ปริ้น 2 อัน, หุ้มยาง) |
| Flywheel Motor Pinion v2 | ข้อต่อเพลามอเตอร์ → ล้อ |
| Ping Pong Ball Shooter v29 | ลำตัว/ลำกล้อง + ท่อแมกกาซีน |

**จุดที่อาจต้องแก้ CAD ก่อนปริ้น (วัดของจริงก่อน):** ① ช่องทางเดินลูก+ระยะล้อ ออกแบบให้ปิงปอง 40 mm — ถ้าลูกบอลไม้เล็กกว่าต้องย่อช่อง ② รูเสียบมอเตอร์ ออกแบบกับมอเตอร์ N20 ของชุด XRP — ถ้ามอเตอร์เราเป็น 130/280 ต้องแก้รู | bracket pan กับที่จับมือถือปริ้นได้เลยไม่ต้องแก้

**เครื่องมือแก้ STEP (ฟรี):** Fusion 360 Personal (แนะนำ) / Onshape (รันในเบราว์เซอร์) / FreeCAD
**ห้ามสเกลทั้งชิ้นใน slicer** เพื่อย่อช่องลูก — รูมอเตอร์/รูสกรูจะย่อตามจนเสียบไม่ได้ ต้องแก้เฉพาะจุดใน CAD (สเกลใน slicer ได้เฉพาะชิ้นไร้รูประกอบ เช่น ตัวล้อ)

### ชั้นจากบนลงล่าง
0. **เสากล้อง (ยึดกับฐาน ไม่หมุน):** มือถือ+ที่จับ เหนือแกน pan พอดี
1. **บนแท่นหมุน:** ตัวยิง flywheel (เงยมุมตายตัว) | แมกกาซีน gravity feed + feeder servo | marker สีที่ปลายลำกล้อง
2. **แท่นหมุน** — เสียบ servo horn + ขันสกรูกลางล็อก (ถ้าโยกเสริม bearing/แหวนรอง)
3. **Pan servo MG945** ใน bracket พิมพ์ 3D ขันสกรูลงฐาน
4. **แผ่นฐาน 400×400 (ไม่หมุน)** — ถ่วงน้ำหนักกัน recoil; อิเล็กทรอนิกส์ทั้งหมดวางชั้นนี้ สายขึ้นส่วนหมุนเผื่อหย่อนรองรับ ±40°

### ไฟล์ 3D print (MG945 = เคสเดียวกับ MG995/996 ใช้ mount ร่วมกันได้)
- ตัวยิง: HIGH-SPEED Ping-Pong Shooter XRP — printables.com/model/951454 (flywheel คู่ + feeder + แมกกาซีนครบ) — **พิมพ์ชิ้นแรก**
- ฐาน pan/tilt: thingiverse.com/thing:3458238 (สกรู M3×10) หรือ makerworld.com/en/models/973248
- ที่จับมือถือ: printables.com/model/472468
- แท่นหมุน/แผ่นฐาน/เสากล้อง: ตัดไม้อัด/อะคริลิกแทนได้ ประหยัดเวลาพิมพ์ ฐานต้องหนัก

### ข้อระวังตอนพิมพ์/ดัดแปลง
- ลูกบอลไม้**แข็ง ไม่ยุบ** (ต่างจากปิงปอง) → ระยะห่างล้อ = Ø ลูก − 1–2 mm โดยให้ยางที่ล้อเป็นตัวยุบ; ล้อ PLA เปลือยลื่น ยิงไม่ออก
- วัด Ø ลูกบอลจริง + ดูมอเตอร์จริง ก่อนพิมพ์เสมอ
- พิมพ์ล้อ infill 50%+ ให้มีมวล ความเร็วไม่ตกตอนปะทะลูก

## 7. วงจร

```
แบต 18650 ×2 (7.4V) ──→ L298N ──→ มอเตอร์ DC ×2 (flywheel, ต่อกลับขั้ว 1 ตัวให้หมุนสวนกัน)
        └──→ buck (ตั้ง 6V) ──→ ไฟ servo ×2 (ขั้ว external ของ shield, ถอด jumper)
PC (Python: OpenCV+UI) ──USB──→ Arduino Uno (StandardFirmata)
        Arduino: PWM → ENA/ENB ของ L298N | D9, D10 → สัญญาณ servo
```

**กราวด์ทุกส่วนต้องต่อร่วมกัน (common GND)** — แบต, buck, L298N, Arduino

จุดพลาดบ่อย: (1) ไม่ถอด jumper shield แล้ว servo ดึงไฟ USB → Uno รีเซ็ตเอง (2) กราวด์ไม่ร่วม → PWM เพี้ยน (3) feeder ดันลูกไม่พ้นมือ → ลูกค้างระหว่างล้อ

## 9. ความเสี่ยงหลัก

| ความเสี่ยง | แผนรับมือ |
|---|---|
| มอเตอร์เป็นแบบมีเกียร์ หมุนช้า | เปลี่ยนเป็นสปริง+servo ปลดล็อก (แรงคงที่ จูนมุมแทน) |

| ป้อมขยับหลังยิง (recoil) | ฐานหนัก/ยึดแน่น, เช็ค marker ใหม่ก่อนนัดถัดไป |
| หน้างานแสงต่างจากที่ซ้อม | ล็อก exposure, เผื่อเวลา calibrate หน้างาน, มีวิดีโอ backup |
| ไฟล์ STEP ไม่พอดีของจริง | วัดของจริงก่อนพิมพ์, แก้ใน Fusion 360 (ฟรี) ห้ามสเกลทั้งชิ้นใน slicer |
